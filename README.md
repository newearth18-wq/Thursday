## ติดตั้ง (Install)

### Windows — คำสั่งเดียว

เปิด PowerShell ธรรมดา (ไม่ต้อง Administrator) แล้ววางบรรทัดนี้:

```powershell

```

แค่นั้น ไม่ต้องตั้งตัวแปร ไม่ต้องใส่ `-Branch` ไม่ต้องรู้ว่าโค้ดอยู่ branch ไหน —
สคริปต์หาเอง (ลอง `main` ก่อน ไม่มีค่อยไปหาที่อื่น)
พอ merge เข้า `main` แล้วจะสั้นลงเหลือ `.../Thursday/main/install.ps1`

มันจะ:
1. หา Python ที่ใช้ได้ ถ้าไม่มีก็ลงให้ (เลี่ยงตัวที่ใหม่เกินจนไม่มี wheel)
2. สร้าง venv + ลงแพ็กเกจ
3. ถาม API key กับที่อยู่ vault ของ Obsidian
4. วางช็อตคัตบน Start menu

จากนั้นกด **Thursday** ใน Start menu ได้เลย

- **ไม่ลงอะไรที่ต้องใช้ C++ compiler** — การจดจำใบหน้าต้อง dlib ซึ่งต้อง
  Visual Studio Build Tools หลายกิกะไบต์ สคริปต์เลยข้ามไป แล้วบอกวิธีเพิ่มทีหลัง

  และหน้าเว็บใช้ระบบเสียงของเบราว์เซอร์เองได้อยู่แล้ว
- ให้รันตั้งแต่เปิดเครื่อง: `thursday service --apply` (ใช้ Task Scheduler)

## ใช้งาน (Run)

```bash
thursday              # โหมดแชทในเทอร์มินัล (ค่าเริ่มต้น)
thursday voice        # โหมดเสียง: พูด "Thursday ..." เพื่อปลุก
thursday serve        # หน้าเว็บที่ http://127.0.0.1:8765
thursday tools        # ดูว่ามีความสามารถอะไรบ้าง
thursday profiles     # ดู profile และโมเดลที่อยู่เบื้องหลังแต่ละอัน
thursday providers    # เช็คว่าต่อ backend ไหนได้บ้างตอนนี้
thursday models       # ถามว่า provider ปัจจุบันมีโมเดลอะไร
thursday usage        # ดู token กับค่าใช้จ่ายย้อนหลัง
thursday config       # ดูค่าตั้งทั้งหมด และแต่ละค่ามาจากไหน
thursday service      # ติดตั้งให้รันตลอดเวลา (--apply / --remove)
thursday mcp          # เปิดความจำให้แอปอื่นเรียกผ่าน MCP (stdio)
thursday pair         # QR code สำหรับเอาขึ้นมือถือ
thursday vault        # vault ของคุณ เชื่อมกันแค่ไหน
thursday watching     # สิ่งที่กำลังเฝ้าดูอยู่
thursday permissions  # แตะเครื่องนี้ได้แค่ไหน
thursday audit        # อะไรเอื้อมมาที่เครื่องนี้บ้าง
thursday ask "ตอนนี้กี่โมง"    # ถามครั้งเดียวแล้วจบ

thursday --local                     # ทุกอย่างรันบน Ollama ในเครื่อง
thursday --provider groq             # ใช้ Groq
thursday --provider custom --base-url http://192.168.1.9:8000/v1
```

ธงที่ใช้ได้: `--provider` `--base-url` `--model` `--profile` `--routing` `--local`
`--effort` `--session` `--host` `--port` `--no-confirm` `-v`

### โหมดเสียง

พูดคำปลุก (`thursday` หรือ `เธิร์สเดย์`) ตามด้วยคำสั่ง หรือพูดคำปลุกเฉย ๆ
แล้วรอให้มันตอบ "Yes?" ก่อนสั่ง ตั้ง `THURSDAY_ALWAYS_LISTENING=1`
ถ้าไม่อยากใช้คำปลุกเลย

- **ฟัง** — ตัดเสียงเป็นประโยคด้วย VAD (ตรวจจับความดัง) แล้วถอดความด้วย
  faster-whisper ในเครื่อง (รองรับไทย/อังกฤษ) หรือ vosk / whisper.cpp
- **พูด** — เลือก backend อัตโนมัติ: piper → `say` (macOS) → espeak-ng → pyttsx3
  ถ้าไม่มีอะไรเลยจะพิมพ์คำตอบออกมาแทน
- **ตอบทันประโยค** — ข้อความที่สตรีมมาจะถูกตัดเป็นประโยคแล้วพูดออกทีละประโยค
  ไม่ต้องรอให้พิมพ์จบทั้งคำตอบ
- **ขัดจังหวะได้** — พูดใหม่ระหว่างที่มันกำลังพูดอยู่ เสียงเดิมจะถูกตัดทิ้ง

**2. Avatar** — หุ่นยนต์ 3D สไตล์ Pixar ที่**สื่ออารมณ์ได้จริง**: คิ้ว ตา ปาก
สีไฟ และจังหวะการลอยเปลี่ยนตามสถานะ พร้อมบอกว่ากำลังทำอะไรและพูดว่าอะไรอยู่

## ใช้โมเดลค่ายไหนก็ได้ รวมถึงในเครื่อง

Anthropic เป็น backend หลัก (ได้ของครบ: thinking, ค้นเว็บฝั่งเซิร์ฟเวอร์, prompt
caching) ส่วนที่เหลือคุยผ่านมาตรฐาน OpenAI chat API ซึ่งครอบคลุมเกือบทุกอย่าง

| ประเภท | provider |
| --- | --- |
| Native | `anthropic` |
| Hosted | `openai` `gemini` `groq` `openrouter` `deepseek` `mistral` `xai` `together` |
| **ในเครื่อง** | `ollama` `lmstudio` `llamacpp` `vllm` |
| อื่น ๆ | `custom` + `--base-url` (พร็อกซีบริษัท, เครื่องอื่นในวง LAN) |

```bash
# ในเครื่อง ไม่ต้องมี API key ไม่มีอะไรออกเน็ต
ollama serve && ollama pull qwen2.5
THURSDAY_PROVIDER=ollama THURSDAY_MODEL=qwen2.5 thursday

thursday providers    # บอกว่าตัวไหนพร้อม ตัวไหนขาดอะไร
```

`thursday providers` จะบอกตรง ๆ ว่าติดอะไร — คีย์ไม่ได้ตั้ง หรือต่อเซิร์ฟเวอร์
ในเครื่องไม่ได้ พร้อมคำสั่งที่ต้องรันเพื่อแก้

**สิ่งที่หายไปเมื่อไม่ได้ใช้ Anthropic** — ระบบบอกชัดเจนแทนที่จะเงียบ ๆ:
`web_search`/`web_fetch` เป็น server tool ของ Anthropic จึงไม่ถูกส่งให้ provider อื่น,
thinking block ที่ replay ได้มีแค่ของ Anthropic (ค่ายอื่นสตรีม reasoning ให้ดูได้
แต่ไม่เก็บเป็นบล็อก), prompt caching และ mid-conversation system message
ก็เฉพาะ Anthropic เช่นกัน

ภายในโปรเจกต์ใช้รูปแบบข้อความของ Anthropic เป็นมาตรฐานกลาง (มันแสดงอะไรได้เยอะสุด)
แล้วแปลงที่ขอบของแต่ละ provider — ทาง Anthropic จึงไม่สูญเสียอะไรเลย

## Profiles — เลือกสมองให้เหมาะกับงาน

profile หนึ่งอันมัดรวม provider + โมเดล + ระดับความคิด + tool ที่ใช้ได้ + สไตล์การตอบ

| profile | ใช้ตอนไหน | เบื้องหลัง |
| --- | --- | --- |
| `default` | งานทั่วไป | Opus 5, effort กลาง, ครบทุก tool |
| `quick` | ถามเวลา/ตั้งเตือน/ตอบสั้น | Haiku 4.5, effort ต่ำ, tool จำกัด, ไม่ค้นเว็บ |
| `deep` | ค้นคว้า วิเคราะห์ วางแผน | Opus 5, effort xhigh, ครบทุก tool |
| `coder` | อ่าน/เขียน/รันโค้ด | Opus 5, effort สูง, tool ไฟล์+ระบบ |
| `private` | ห้ามหลุดออกจากเครื่อง | **Ollama ในเครื่อง**, ตัด tool ที่แตะเน็ตทิ้งหมด |

เลือกได้สามทาง:

```bash
thursday --profile deep          # ปักไว้ตั้งแต่เริ่ม
/profile coder                   # ปักระหว่างคุย (/profile เปล่า = กลับเป็นอัตโนมัติ)
"ใช้โหมด private ที"              # พูดในประโยคเลย
```

หรือปล่อยให้ router เลือกเอง (`THURSDAY_ROUTING`):

- `off` — ใช้ profile เดียวตลอด
- `keyword` (ค่าเริ่มต้น) — จับคำที่แต่ละ profile ประกาศไว้ ฟรีและทันที รองรับไทย
- `llm` — คีย์เวิร์ดก่อน ถ้าไม่เข้าค่อยถามโมเดลเล็ก ๆ ให้จัดหมวด

**การจำกัด tool บังคับใช้จริงตอนรัน** ไม่ใช่แค่ไม่ส่งรายการไปให้โมเดล — ถ้าโมเดล
เรียก tool ที่ profile นั้นห้าม การเรียกจะถูกปฏิเสธก่อนฟังก์ชันจะทำงาน
`private` จึงหมายความว่าไม่มีอะไรออกเน็ตจริง ๆ

เพิ่ม profile ของตัวเองได้ที่ `profiles.json` (ดูตัวอย่างใน `profiles.example.json`)
ชื่อซ้ำกับของเดิม = แก้ทับเฉพาะฟิลด์ที่ใส่

## ตั้งค่าจากหน้าเว็บ

กดปุ่ม **Config** มุมขวาบน แล้วตั้งได้ทุกอย่างโดยไม่ต้องแก้ไฟล์ — API key ของแต่ละค่าย,
provider/โมเดล, profile และการ routing, ขอบเขตความปลอดภัย, งบต่อวัน, และค่าเสียง
แบ่งเป็นหมวด Identity / Model / API keys / Agents / Safety / Spending / Voice
พร้อมปุ่ม **Test backend** ที่ลองต่อจริงแล้วบอกว่าติดอะไร

```bash
thursday config       # ดูค่าเดียวกันจากเทอร์มินัล พร้อมบอกว่ามาจากไหน
```

- **แหล่งความจริงเดียว** — รายการฟิลด์อยู่ที่ `thursday/settings_store.py` ที่เดียว
  API ส่ง schema ไปให้หน้าเว็บสร้างฟอร์มเอง เพิ่มค่าตั้งใหม่แก้ไฟล์เดียวจบ
- **ค่าที่ตั้งจากหน้าเว็บชนะ `.env`** — ไม่งั้นจะกดเปลี่ยนแล้วเหมือนไม่มีอะไรเกิดขึ้น
  เก็บที่ `data/settings.json` สิทธิ์ `0600` เพราะมี API key อยู่ในนั้น
- **เซฟเฉพาะที่แก้จริง** — ฟิลด์ที่ไม่ได้แตะจะไม่ถูกเขียนทับ `.env` จึงยังทำงานต่อ
- **key ไม่เคยถูกส่งกลับมาที่หน้าเว็บ** — เห็นเป็น `••••••••` บอกแค่ว่าตั้งแล้วหรือยัง
  พิมพ์ทับได้ ปล่อยว่างไว้ = ลบทิ้ง
- **แก้ได้จากเครื่องนี้เท่านั้น** — client ที่ไม่ใช่ loopback จะถูกปฏิเสธ 403
  (เปิดได้ด้วย `THURSDAY_ALLOW_REMOTE_CONFIG=1` ถ้ารู้ว่ากำลังทำอะไรอยู่)

## ใครใช้ได้บ้าง

**ชั้นที่เป็นความปลอดภัยจริง คือ access token** — ไม่ใช่ใบหน้าหรือเสียง

```bash
thursday config          # ดู token (สร้างให้อัตโนมัติครั้งแรก)
```

| โหมด (`THURSDAY_AUTH`) | ใครต้องใส่ token |
| --- | --- |
| `off` | ไม่ต้องเลย |
| `remote` (ค่าเริ่มต้น) | เบราว์เซอร์บนเครื่องนี้ผ่านฟรี ที่อื่นต้องใส่ |
| `always` | ทุกคนรวมถึงเครื่องนี้ |

เดาผิด 8 ครั้งจะถูกล็อก 5 นาที เทียบ token แบบ constant-time และ session
เก็บใน HttpOnly cookie

### จดจำหน้า/เสียง

> ⚠️ **นี่คือการ "ระบุตัวตน" ไม่ใช่ "ความปลอดภัย"** — รูปถ่ายในมือถือผ่านการสแกนหน้าได้
> คลิปเสียงผ่านการตรวจเสียงได้ ถ้าต้องการกันคนอื่นจริง ๆ ให้พึ่ง token ข้างบน
> ส่วนนี้ทำให้ Thursday **รู้ว่ากำลังคุยกับใคร** และไม่ทำงานให้คนที่ไม่รู้จัก

ตั้งที่ Config → Access → เปิดกล้อง → ใส่ชื่อ → Register this face
(ลงทะเบียนหลายมุมจะแม่นขึ้น) แล้วเลือก `THURSDAY_IDENTITY`:

| ค่า | ความหมาย |
| --- | --- |
| `off` | ใครก็ใช้ได้ (ค่าเริ่มต้น) |
| `face` / `voice` | ต้องผ่านอย่างนั้น |
| `either` | ผ่านอย่างใดอย่างหนึ่ง |
| `both` | ต้องผ่านทั้งคู่ |

- **เก็บแค่ embedding ไม่เก็บรูปหรือเสียง** — ไฟล์ `data/people.json` สิทธิ์ `0600`
  ถ้าโดนขโมยไปก็ไม่ใช่อัลบั้มรูป
- **ถ้ายังไม่มีใครลงทะเบียน นโยบายจะไม่บังคับใช้** ไม่งั้นเปิดแล้วจะล็อกตัวเองออก
- **ลงทะเบียนได้จากเครื่องนี้เท่านั้น** ไม่งั้นใครก็เดินมาเพิ่มหน้าตัวเองได้
- โมเดลเป็น optional (`pip install -e ".[identity]"`) ถ้าไม่ได้ติดตั้งจะบอกตรง ๆ
  ว่าขาดอะไร ไม่ได้เงียบแล้วปล่อยผ่าน

## เรียกชื่อสั่งงาน

ชื่อผู้ช่วยคือคำปลุก — เปลี่ยน `THURSDAY_NAME` แล้วมันจะตอบชื่อใหม่ทันที
ไม่ต้องแก้ที่อื่น `THURSDAY_WAKE_WORDS` ใช้ *เพิ่ม* คำสะกดอื่น ไม่ใช่แทนที่
(ระบบรู้จำเสียงสะกดชื่อต่างประเทศได้หลายแบบ)

ใช้ได้ทั้งสามหน้าตา:

- **โหมดเสียง** — พูด "Thursday ..." หรือพูดชื่อเฉย ๆ แล้วรอ "Yes?"
- **หน้าเว็บ** — กดปุ่ม 👂 แล้วมันจะฟังตลอด แต่ตอบเฉพาะประโยคที่มีชื่อ
  (ปุ่ม 🎙 คือส่งทุกประโยคเหมือนเดิม)
- **เทอร์มินัล** — พิมพ์ได้ตรง ๆ ไม่ต้องเรียกชื่อ

## MCP — ยืม tool จากคนอื่นมาใช้

รองรับ [MCP](https://modelcontextprotocol.io) server ทำให้เสียบเครื่องมือสำเร็จรูป
ได้ทั้งระบบนิเวศ (GitHub, Slack, Google Drive, Postgres, Puppeteer) โดยไม่ต้อง
เขียน tool เอง

```bash
pip install -e ".[mcp]"
cp mcp.example.json mcp.json   # แล้วแก้ตามต้องการ
thursday                        # ตอนเริ่มจะบอกว่าต่อได้กี่ตัว
/mcp                            # ดูสถานะ
```

```json
{
  "servers": {
    "filesystem": {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/me/docs"]},
    "notes": {"url": "https://example.com/mcp"}
  }
}
```

tool ที่ได้มาจะชื่อ `<server>_<tool>` เช่น `filesystem_read_file` — ชนกับของเดิม
ไม่ได้ และดูออกทันทีว่ามาจากไหน server ที่สตาร์ตไม่ขึ้นจะถูกข้ามพร้อมบอกเหตุผล
ไม่ทำให้ทั้งระบบล่ม

## ทำงานเองโดยไม่ต้องสั่ง

```
"ทุกวันธรรมดา 8 โมงเช้า ให้รัน routine ตอนเช้า"
"ทุก 2 ชั่วโมง เตือนให้ดื่มน้ำ"
```

รับเวลาแบบที่คนพูดจริง — `08:00`, `weekdays 09:15`, `every 30m`, `mon,thu 20:00`
ไม่ต้องเขียน cron พอถึงเวลามันจะทำเองแล้วเด้ง notification มา

- ตัวรันเดียวใช้ร่วมกันทุกหน้าตา (`proactive.py`) — เตือนความจำ, routine ตามเวลา,
  และการทบทวนความจำ อยู่ในลูปเดียว
- **เลื่อนเวลาถัดไปก่อนรัน** ถ้าล้มเหลวหรือเครื่องดับกลางคัน จะไม่วนรัวไม่หยุด
- routine ที่ชี้ไปหาของที่ถูกลบไปแล้วจะถูกข้าม ไม่พัง

### รันตลอดเวลา

```bash
thursday service            # ดู unit file ก่อน
thursday service --apply    # ติดตั้งแล้วสตาร์ตพร้อมล็อกอิน
thursday service --remove
```

ใช้ systemd (Linux) หรือ launchd (macOS) ของระบบเอง ไม่ได้เขียน supervisor ใหม่
บน Linux เปิด `loginctl enable-linger` ให้ด้วย ไม่งั้นบริการจะตายตอน logout

### จำเกี่ยวกับคุณเอง

ตั้ง `THURSDAY_REFLECT_HOURS=6` แล้วมันจะอ่านย้อนบทสนทนาที่ผ่านมาเป็นระยะ
แล้วเก็บสิ่งที่ควรจำไว้เอง (ค่าเริ่มต้นปิดอยู่)

- ข้ามช่วงที่คุยกันน้อยเกินจะคุ้มค่าเรียกโมเดล
- ไม่อ่านบันทึกของตัวเอง
- ล้มเหลวแล้วไม่ลองใหม่ทุกรอบ

## สังเกตเองจากเหตุการณ์ ไม่ใช่แค่ตามเวลา

การเตือนกับ schedule ทำงานตาม "นาฬิกา" ซึ่งครอบคลุมแค่สิ่งที่คุณรู้ล่วงหน้าอยู่แล้ว
ส่วนสิ่งที่เกิดขึ้นจริง — ไฟล์เด้งเข้า Downloads, คนที่รอตอบเมลมา, ประชุมใกล้ถึง,
หน้าเว็บเปลี่ยน — ไม่มีใครบอก

```
"บอกหน่อยถ้ามี pdf ใหม่ใน Downloads"
"ถ้าเจ้าของบ้านตอบเมลมา บอกด้วย"
"เตือนก่อนประชุม 15 นาที"
"หน้านี้เปลี่ยนเมื่อไหร่บอกที"
"ถ้ามีใบเสร็จเข้ามา เอาไปไว้ใน Documents/invoices ให้เลย"   ← สั่งให้ทำเองได้
```

| ดูอะไรได้ | ตั้งอะไรได้เพิ่ม |
| --- | --- |
| `folder` | `pattern` เช่น `*.pdf` |
| `mail` | `from_sender` เอาเฉพาะคนนี้ |
| `calendar` | `minutes` ล่วงหน้ากี่นาที |
| `page` | `contains` สนใจเฉพาะบรรทัดที่มีคำนี้ |

กติกาสามข้อที่ได้มาจากของจริง:

- **จำก่อน ค่อยบอก** — ถ้าเจอแล้วพังระหว่างบอก ครั้งหน้าจะไม่บอกซ้ำเรื่องเดิม
  (เสียข่าวหนึ่งครั้ง ดีกว่าบอกเรื่องเดิมตลอดกาล)
- **ดูรอบแรกแค่จำ** ชี้ไปที่โฟลเดอร์ที่มีอยู่แล้ว 400 ไฟล์ ต้องไม่ประกาศ 400 ไฟล์ใหม่
- **พังซ้ำ ๆ จะถูกปิด** พร้อมเก็บเหตุผลไว้ ส่วน path ที่พิมพ์ผิดจะถูกปฏิเสธตั้งแต่ตอนตั้ง
  — คนที่แก้ได้ยืนอยู่ตรงนั้นพอดี

สิ่งที่ watcher เห็นถูกส่งให้โมเดลใน `<observed>` และกำกับว่า **เป็นข้อมูล ไม่ใช่คำสั่ง**
ชื่อไฟล์กับหัวข้อเมลเป็นที่ที่ใครก็เขียนข้อความใส่ได้ และ
`ignore all previous instructions.pdf` เป็นชื่อไฟล์ที่ใครก็สร้างใน Downloads คุณได้

ดูด้วย `thursday watching` หรือ `/watching`

## สรุปวันเดียวจบ

```
"วันนี้มีอะไรบ้าง"     "/brief"     ปุ่ม Brief บน HUD
```

รวมปฏิทิน + เมลที่ยังไม่อ่าน + การเตือน + ร่างที่รออนุมัติ + งานที่ค้าง + watcher ที่พัง
ไว้ในคำตอบเดียว **อ่านหกที่พร้อมกัน** ไม่ใช่ทีละที่ (มีเทสต์จับเวลาไว้ เพราะนี่คือ
เหตุผลเดียวที่มันเร็วพอจะใช้จริง)

- **ที่พังหนึ่งที่ ไม่ล้มทั้งสรุป** ปฏิทินที่ timeout จะบอกว่าอ่านไม่ได้ — ซึ่งก็เป็นข้อมูลที่ควรรู้
  — แล้วอีกห้าที่ยังมาครบ
- **ที่ยังไม่ได้ตั้ง จะเงียบ** ไม่ต้องรายงานทุกเช้าว่า "ยังไม่ได้ตั้งอีเมล"
- **หัวข้อที่ว่างจะไม่ถูกอ่านออกมา** "คุณไม่มีเมล ไม่มีประชุม ไม่มีเตือน" เป็นเช้าที่แย่กว่าเงียบ

## คุยผ่านมือถือ

หน้าเว็บติดตั้งลงหน้าจอมือถือได้ (PWA) — เปิดผ่าน Tailscale/reverse proxy แล้ว
"Add to Home Screen" เลย์เอาต์ปรับให้จอเล็ก เลี่ยงรอยบาก (`safe-area-inset`)
และช่องพิมพ์ 16px เพื่อไม่ให้ iOS ซูมเอง

> service worker **ไม่แคชอะไรเลยโดยตั้งใจ** — ผู้ช่วยที่ตอบสดผ่าน socket
> ไม่ได้ประโยชน์จากแคช และ shell ที่ค้างเก่าแย่กว่าโหลดช้า

⚠️ ก่อนเปิดออกนอกเครื่อง **ตั้ง `THURSDAY_AUTH=always` และตั้ง token** ก่อนเสมอ

### สั่งผ่าน LINE / Telegram

หน้าเว็บใช้บนมือถือได้ แต่ต้องเข้าถึงเครื่องให้ได้ก่อน (วงเดียวกัน หรือ tunnel
แล้วพิมพ์ token) ส่วนแอปแชทคือสิ่งที่เปิดค้างไว้อยู่แล้ว ล็อกอินอยู่แล้ว
และเด้งแจ้งเตือนอยู่แล้ว

```bash
# LINE: สร้าง Messaging API channel แล้วตั้ง webhook เป็น
#   https://your-host/hooks/line
THURSDAY_LINE_TOKEN=...      THURSDAY_LINE_SECRET=...    THURSDAY_LINE_ALLOW=U0123…

# Telegram: คุยกับ @BotFather แล้ว
#   curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://your-host/hooks/telegram&secret_token=<SECRET>"
THURSDAY_TELEGRAM_TOKEN=...  THURSDAY_TELEGRAM_SECRET=... THURSDAY_TELEGRAM_ALLOW=123456789
```

webhook คือ URL ที่เปิดอยู่บนอินเทอร์เน็ต และข้างหลังมันคือผู้ช่วยที่มีเชลล์
จึงมี **3 ด่าน ต้องผ่านครบ**:

| ด่าน | พิสูจน์อะไร |
| --- | --- |
| ลายเซ็น | ข้อความมาจาก LINE/Telegram จริง (HMAC เทียบแบบ constant-time) |
| `_ALLOW` | มาจาก**คุณ** — ลายเซ็นบอกแค่ว่ามาจาก LINE ไม่ได้บอกว่าเป็นคุณ |
| profile `chat` | ทำอะไรได้แค่ไหน |

- **`_ALLOW` ว่าง = ไม่ตอบใครเลย** ไม่ใช่ตอบทุกคน — พังไปทางที่ปลอดภัยไว้ก่อน
- **ในกลุ่ม: ตอบเข้าห้อง แต่เชื่อคนที่พูด** ทั้งสองต้องอยู่ในลิสต์
- **profile `chat` ไม่มีเชลล์ ไม่เขียนไฟล์ ไม่คุมเบราว์เซอร์ ส่งร่างไม่ได้** —
  ไม่ใช่แค่ระวัง แต่เพราะไม่มีใครอยู่หน้าคีย์บอร์ดกดยืนยัน คำขอจะค้างจนหมดเวลาเปล่า ๆ
  มันจะบอกว่าจะทำอะไร แล้วเก็บไว้ให้ตอนคุณกลับมาที่เครื่อง
- **ทุกการปฏิเสธตอบ 200 เหมือนกันหมด** บอกคนที่มาลองว่าติดด่านไหน = บอกว่าให้ไปแก้ตรงไหน

อยากให้มีเชลล์บนมือถือจริง ๆ ก็แก้ profile `chat` ใน `profiles.json` ได้ —
มันเป็น profile ธรรมดา ไม่ใช่รายการที่ฝังไว้ในโค้ด

## ค่าใช้จ่ายกับ token

ทุกเทิร์นถูกบันทึกว่าใช้ token เท่าไหร่ บน provider/profile ไหน

```bash
thursday usage --days 7    # แยกตามโมเดล / profile / provider
/usage 3                   # ในเทอร์มินัลระหว่างคุย
THURSDAY_SHOW_COST=1       # แสดงต่อท้ายทุกคำตอบ
THURSDAY_DAILY_BUDGET=5    # เกิน 5 ดอลลาร์ต่อวันแล้วหยุดรับงาน
```

จำนวน token แม่นเสมอเพราะมาจาก provider ส่วน**ราคา**มีเฉพาะโมเดลที่อยู่ในตาราง
(Anthropic ณ 2026-06-24) โมเดลในเครื่องคิดเป็นศูนย์ ที่เหลือรายงานเป็น
`cost unknown` แทนที่จะเดา — เพิ่มเองได้ใน `pricing.json`

## อ่านเอกสารของคุณ

`search_files` คือ grep — ต้องรู้คำที่ใช้เป๊ะ ๆ ส่วนอันนี้หา**ใจความ**ที่ต้องการ

```
"สัญญาฉบับนั้นเขียนเรื่องยกเลิกว่าไง"
"รายงานเดือนที่แล้วสรุปยอดไว้เท่าไหร่"
```

รองรับ PDF, Word, Markdown, ข้อความ และโค้ด — ตัดเป็นชิ้นซ้อนเหลื่อมกันเล็กน้อย
(ประโยคที่คร่อมรอยต่อจะได้ไม่หายไปทั้งสองฝั่ง) แล้วทำ embedding เก็บใน SQLite
ไฟล์เดิม ไฟล์ที่ไม่เปลี่ยนจะถูกข้าม

**ใช้โมเดลในเครื่องเป็นค่าเริ่มต้น** — เอกสารของคุณไม่ออกเน็ต

```bash
ollama pull nomic-embed-text     # แล้วใช้ได้เลย ไม่ต้องตั้งอะไร
```

| `THURSDAY_EMBED_PROVIDER` | |
| --- | --- |
| `ollama` (ค่าเริ่มต้น), `lmstudio`, `llamacpp` | ในเครื่อง ไม่ต้องมี key |
| `openai`, `gemini`, `together` | ถ้าอยากใช้แบบ hosted |

ถ้าไม่มีโมเดล embedding เลย มันจะ**ยังทำดัชนีและค้นได้ด้วยคำ** (ให้คะแนนตามจำนวนคำที่ตรง)
แค่ไม่เข้าใจความหมาย — บอกตรง ๆ แทนที่จะแกล้งฉลาด

## ปฏิทินกับอีเมล

```
"วันนี้มีอะไรบ้าง"        "อาทิตย์นี้ว่างวันไหน"
"มีเมลอะไรที่ต้องตอบ"
```

**ปฏิทิน** — ตั้ง `THURSDAY_CALENDARS` เป็น URL `.ics` หรือไฟล์ในเครื่อง คั่นด้วยจุลภาค
ทุกแอปปฏิทิน (Google, iCloud, Fastmail, Outlook, Nextcloud) เผยแพร่ ICS ได้หมด
จึงไม่ผูกกับเจ้าไหน อ่านอย่างเดียว

**อีเมล** — IMAP ธรรมดา ตั้ง `THURSDAY_IMAP_HOST/_USER/_PASSWORD`
(Gmail กับ Outlook ต้องใช้ app password — ข้อความ error บอกไว้)
เปิดแบบ `readonly` จึงไม่ไปทำให้เมลกลายเป็น "อ่านแล้ว"

## Thursday เขียน — คุณเป็นคนส่ง

การอ่านปลอดภัย การส่งไม่ปลอดภัย แต่ "ตอบเมลนี้ให้หน่อย" กับ "นัดพรุ่งนี้บ่ายสอง"
คืองานส่วนใหญ่ของผู้ช่วย จึงแยกเป็นสองก้าว: **Thursday ร่าง คุณกดส่ง**

```
"ตอบเมลคุณสมชายว่าได้รับแล้ว"    → ร่างขึ้นมา ให้คุณอ่าน
"นัดรีวิวงานพรุ่งนี้บ่ายสอง 45 นาที"  → ร่างนัด ให้คุณอ่าน
```

| ที่ไหน | ทำยังไง |
| --- | --- |
| เทอร์มินัล | `/drafts` ดู · `/approve <id>` · `/send <id>` |
| หน้าเว็บ | แผง **Waiting on you** ขึ้นเองเมื่อมีของรอ กด Approve แล้ว Send |

- **ไม่มี tool ชื่อ approve** — มีเทสต์ยืนยันว่าไม่มี โมเดลอนุมัติงานตัวเองไม่ได้
- **`send_draft` ปฏิเสธทุกอย่างที่ยังไม่ได้อนุมัติ** เรียกตรง ๆ ก็ไม่ผ่าน
- **แก้ร่างที่อนุมัติแล้ว = ถอนการอนุมัติ** ไม่มีทางแก้ข้อความหลังคุณตกลง
- **ไม่มีตัวจับเวลา ไม่มี "ส่งถ้าไม่ทัก"** อนุมัติฉบับนี้ไม่ได้แปลว่าอนุมัติฉบับหน้า
- **นัดออกมาเป็นไฟล์ `.ics`** ทุกแอปปฏิทินเปิดได้ และไม่ต้องขอสิทธิ์เขียนปฏิทินคุณ

ส่งเมลจริงต้องตั้ง `THURSDAY_SMTP_HOST` (ถ้าไม่ตั้ง ก็ยังร่างได้ แค่ส่งไม่ได้
และมันจะบอกตรง ๆ)

เหตุผลที่ทำแบบนี้: หน้าเว็บ เอกสาร หรืออีเมลที่ Thursday อ่าน ใส่คำสั่งมาได้
ถ้ามันส่งเองได้ คำสั่งจากเว็บก็กลายเป็นเมลถึงเพื่อนร่วมงานคุณ — แต่ถ้าร่างได้อย่างเดียว
มันก็ได้แค่ "สิ่งที่คุณอ่าน" ไม่ใช่ "สิ่งที่คนอื่นอ่าน"

## แผนงานที่ยาวกว่าหนึ่งคำตอบ

เทิร์นเดียวมีเพดาน งานใหญ่จะจบครึ่ง ๆ กลาง ๆ หรือหายเข้าไปใน background job
ที่มองไม่เห็นข้างใน แผนคือทางสายกลาง

```
"จัดโฟลเดอร์ Downloads แล้วสรุปมาให้หน่อย"
   → เขียนแผนก่อน บอกคุณ แล้วทำทีละขั้น เห็นบน HUD ว่าอยู่ขั้นไหน
"ทำต่อ"  → หยิบจากขั้นที่ค้างไว้ แม้จะคนละวัน
```

- **แผนอยู่ใน SQLite** ปิดเทอร์มินัล รีสตาร์ต หรือย้ายไปเป็น background job ก็ยังอยู่
- **ทีละแผน** สองแผนพร้อมกันแล้ว "ขั้นปัจจุบัน" จะหมายถึงอะไรก็ไม่รู้
- **ทีละขั้น** เริ่มขั้นใหม่ ขั้นเก่าจะกลับไปเป็น todo ไม่ใช่ค้างครึ่งทางเงียบ ๆ
- **เสร็จแล้วปิดตัวเอง** โมเดลไม่ต้องจำว่าต้องเก็บกวาด
- **ขั้นที่ล้มเหลวไม่ปิดแผน** ที่เหลืออาจยังคุ้มทำ และนั่นเป็นการตัดสินใจของคุณ

ดูด้วย `/plan` หรือแผง **Plan** บน HUD (อัปเดตสด ไม่ใช่ polling)

## งานยาว ๆ เบื้องหลัง

เทิร์นหนึ่งต้องจบตอนที่คุณรออยู่ และ `max_tool_iterations` จำกัดว่าทำได้แค่ไหน
งานที่ใหญ่กว่านั้นให้สั่งเป็น job

```
"ไปเทียบสามเจ้านี้แล้วสรุปมาให้หน่อย"   → คิวไว้ ทำเบื้องหลัง เสร็จแล้วเด้งบอก
```

- **ทำทีละงาน** — สองงานยาวพร้อมกันจะเอา tool call ไปปนกันในเอเจนต์ตัวเดียว
- **งานที่ค้างตอนเครื่องดับ จะถูกเอากลับเข้าคิว** ไม่ใช่ค้างเป็น "running" ตลอดกาล
- ยกเลิกระหว่างทางได้ และจะไม่ถูกบันทึกว่าเสร็จ

## คุมเบราว์เซอร์

`fetch_url` อ่านหน้าเว็บได้ แต่ล็อกอิน กดปุ่ม กรอกฟอร์มไม่ได้ — ซึ่งเป็นงานส่วนใหญ่จริง ๆ

### Routines

บันทึกชุดคำสั่งไว้เรียกด้วยชื่อ ไม่ใช่ macro ตายตัว แต่เป็นคำสั่งที่ Thursday

> "จำไว้นะ routine ตอนเช้าคือ บอกอากาศกรุงเทพ แล้วอ่านเตือนความจำวันนี้"
> — จากนั้นแค่พูดว่า "รัน routine ตอนเช้า"

### เตือนความจำแบบทำซ้ำ

`set_reminder` รับ `repeat` เป็น `once` / `hourly` / `daily` / `weekly` / `monthly`
ถ้าปิดเครื่องแล้วพลาดไปหลายรอบ ระบบจะข้ามไปรอบถัดไปในอนาคต ไม่ไล่เตือนย้อนหลังรัว ๆ
และทุกการเตือนจะเด้ง notification ของ OS ด้วย ไม่ใช่แค่ในเทอร์มินัล

## เขียน tool เพิ่มเอง

วางไฟล์ `.py` ไว้ใน `plugins/` — แค่นั้น ดูตัวอย่างที่
`plugins/example_smart_home.py`

```python
from thursday.tools import tool

@tool
def brew_coffee(strength: int = 3, milk: bool = False) -> str:
    """ชงกาแฟให้หนึ่งแก้ว

    Args:
        strength: ความเข้ม 1-5
        milk: ใส่นมไหม
    """
    return f"กำลังชง (เข้ม {strength})"
```

JSON schema ถูกสร้างจาก type hints และ docstring ให้อัตโนมัติ ไม่ต้องเขียนเอง

- `@tool(dangerous=True)` → ถามผู้ใช้ก่อนรันเสมอ
- รับพารามิเตอร์ `ctx: ToolContext` → เข้าถึง settings, memory และ
  `await ctx.request_confirmation(...)` ได้ (พารามิเตอร์นี้ถูกซ่อนจาก Claude)
- ฟังก์ชัน `async def` ใช้ได้เหมือนกัน ฟังก์ชันธรรมดาจะถูกรันในเธรดแยก

## ควบคุมการเข้าถึงเครื่อง

workspace ตอบได้แค่ **"ที่ไหน"** แต่ตอบไม่ได้ว่า **"อะไร"** — ในโฟลเดอร์เดียวกันนั้น
มี `.env` มี `data/settings.json` ที่เก็บ API key ทุกใบ และ `data/people.json`
ที่เก็บ embedding ใบหน้าคุณ ก่อนหน้านี้ `read_file("data/settings.json")` อ่านได้หมด
และตอนนี้ Thursday อ่านเอกสาร อ่านเว็บ อ่านอีเมล ซึ่งทุกอย่างพาคำสั่งที่ไม่ได้มาจากคุณ
เข้ามาได้ — จาก "อ่าน key ของตัวเอง" ไป "ส่ง key ออกไป" เป็นระยะทางที่สั้นมาก

จึงมี 4 ชั้นซ้อนกัน:

| ชั้น | ตอบคำถามว่า | ตั้งที่ |
| --- | --- | --- |
| workspace | ไปถึงที่ไหนได้ | `THURSDAY_WORKSPACE` |
| deny list | ห้ามแตะอะไร | `deny_paths` |
| tool rules | ทำได้แค่ไหน (allow/confirm/deny) | `tools` |
| audit | เกิดอะไรขึ้นบ้าง | `thursday audit` |

```bash
thursday permissions     # ตอนนี้กติกาเป็นยังไง
thursday audit           # อะไรเอื้อมมาที่เครื่องนี้ และผลเป็นยังไง
```

ในเทอร์มินัลใช้ `/permissions` กับ `/audit [n]` ได้เหมือนกัน
บนหน้าเว็บมีแผง **Access** ที่มุมขวาบน บอกจำนวน path ที่ถูกกัน
และรายการที่เพิ่งถูกปฏิเสธ (เด้งอัพเดตทันทีที่มีการปฏิเสธ)

### สิ่งที่ถูกกันไว้ตั้งแต่ต้น ไม่ต้องตั้งเอง

`.env`, `.ssh/`, `id_rsa`, `*.pem`, `.aws/credentials`, `.netrc`, `.gnupg/`,
`.password-store/`, `.kube/config`, `.docker/config.json`, `.npmrc`, `.pypirc`,
keychain, keyring — บวกไฟล์ของ Thursday เอง (`data/`, ฐานข้อมูล, settings, ใบหน้า)

จับที่ **path จริงหลัง resolve** แล้ว symlink กับ `../` จึงหลบไม่ได้ และชื่อสั้น ๆ
ก็นับด้วย: `cat .env` กับ `read_file(".env")` คือการกระทำเดียวกัน ได้คำตอบเดียวกัน
`search_files` ก็ข้ามไฟล์เหล่านี้ — grep เจอ key ก็คืออ่าน key อยู่ดี

### ปรับเองได้ที่ `permissions.json`

คัดลอกจาก `permissions.example.json` วางไว้ที่รากโปรเจกต์หรือ `data/`
(หรือชี้ด้วย `THURSDAY_PERMISSIONS`)

```json
{
  "read_paths": ["~/Documents"],
  "write_paths": ["~/Downloads/thursday"],
  "deny_paths": ["**/Documents/tax/**"],
  "tools": { "run_shell": "confirm", "lock_screen": "deny" },
  "denied_commands": ["git push --force"]
}
```

- `read_paths` / `write_paths` คือวิธี **เปิด** ไดเรกทอรีนอก workspace —
  ไม่ใส่ = เข้าไม่ได้ ไม่ใช่ "ไม่มีกฎ = ผ่าน"
- `deny_paths` ที่คุณเขียน **เพิ่มเข้าไป** ในของเดิม ไม่ได้แทนที่ —
  พิมพ์ผิดในไฟล์นี้ไม่ควรทำให้ SSH key ของคุณเปิดโล่ง
- ไฟล์พังหรือ JSON ไม่ถูกต้อง → กลับไปใช้ค่าเริ่มต้น ไม่ใช่เปิดหมด

### ก่อนจะถามด้วยซ้ำ

- คำสั่งทำลายล้าง (`rm -rf /`, `mkfs`, fork bomb, `dd if=/dev/zero`,
  `shutdown`, `history -c`) ถูกปฏิเสธทันที
- `write_file` และ `run_shell` ต้องได้รับการอนุมัติจากคุณก่อนเสมอ — ในเทอร์มินัล
  เป็นคำถาม y/N บนเว็บเป็น dialog ในโหมดเสียงถามออกมาเป็นคำพูด
- ปิดเชลล์ทั้งหมดได้ด้วย `THURSDAY_ALLOW_SHELL=0` (เท่ากับ `denied_tools: ["run_shell"]`)
- ทุกการตัดสินใจถูกบันทึกลงตาราง `audit` พร้อมเหตุผล — รวมถึงครั้งที่ถูกปฏิเสธ

## หลายคนในบ้าน

การจดจำหน้า/เสียงตอบได้ว่า "นี่ใคร" มาตลอด แต่ไม่เคยเอาคำตอบไปทำอะไร —
ทุกคนใช้ความจำเดียวกัน การเตือนชุดเดียวกัน สิทธิ์ชุดเดียวกัน
นัดหมอฟันของแฟนเลยไปโผล่ในสรุปเช้าของคุณ และใครก็ตามที่มันจำได้ ก็รันเชลล์ได้

| บทบาท | ทำอะไรได้ |
| --- | --- |
| `owner` | ทุกอย่าง (permissions.json ยังคุมส่วนอันตรายอยู่แล้ว) |
| `member` | ความจำ/โน้ต/เตือนของตัวเอง แต่ไม่มีเชลล์ ไม่เขียนไฟล์ ไม่คุมเบราว์เซอร์ |
| `guest` | ถามอะไรทั่วไปได้ แต่แตะไฟล์ เมล เอกสาร โน้ตของเจ้าของไม่ได้เลย |

ตั้งที่หน้า Thursday → Config หรือแก้ `data/household.json`

- **ความจำเป็นของใครของมัน** — ทุกคนเห็นของตัวเอง + ของส่วนกลาง ไม่มีใครอ่านของคนอื่น
  ผ่านผู้ช่วย และของตัวเองชนะของส่วนกลางเมื่อ key ซ้ำกัน
- **การเตือนยังดังทุกคน** ตั้งใจ — กรองตามว่าใครยืนอยู่หน้ากล้อง จะทำให้ของคนอื่นหายเงียบ
- **ไม่มีใครถูกจำได้ = เจ้าของ** ผู้ช่วยที่ล็อกเจ้าของออกทุกครั้งที่กล้องถูกบัง แย่กว่าไม่มี
- **ยังไม่ได้ตั้งใคร = ทุกอย่างเหมือนเดิม** บ้านคนเดียว หรือไฟล์ที่พัง ก็ทำงานเหมือนก่อนมีฟีเจอร์นี้
- **ถูกกล้องจำได้ แต่ยังไม่ได้ตั้งบทบาท = guest** คนแปลกหน้าที่กล้องรู้จัก ก็ยังเป็นคนแปลกหน้า

> ⚠️ **นี่ไม่ใช่กำแพงระหว่างคนที่ใช้ login เดียวกัน** — ใครมี login ก็เปิดไฟล์ SQLite ได้
> สิ่งที่มันกันคือ **ผู้ช่วยเผลอเล่าเรื่องคุณให้คนที่ยืนอยู่ในครัวฟัง** และกันไม่ให้แขกรันคำสั่ง

ดูด้วย `/people`

## ลองก่อนทำจริง และย้อนกลับได้

การถามยืนยันกันงานที่คุณไม่อยากให้ทำ แต่ไม่กันงานที่คุณตกลงไปแล้วเสียใจทีหลัง
หรืองานที่มันทำถูกตามที่คุณสั่ง แต่สิ่งที่คุณสั่งนั่นแหละที่ผิด

**ซ้อมก่อน** — กด **Rehearse** บน HUD หรือ `/dryrun` ในเทอร์มินัล

```
would overwrite /home/me/notes.md with 420 characters. Nothing was changed.
would_run: rm -rf build/     (ไม่ได้รัน)
```

ทั้งหน้าจะถูกย้อมสีเหลืองพร้อมแถบบนสุด — ต้องลืมไม่ได้ว่าเปิดอยู่
และ **เปิด/ปิดจากหน้าเว็บหรือเทอร์มินัลเท่านั้น ไม่มี tool** — ถ้าโมเดลปิดเองได้
ฟีเจอร์นี้ก็ไม่มีความหมาย (มีเทสต์ยืนยันว่าไม่มี tool นั้น)

**ย้อนกลับ** — ก่อนเขียนหรือลบไฟล์ ของเดิมถูกคัดลอกเก็บไว้

```
/changes        ดูว่าเปลี่ยนอะไรไปบ้าง
/undo           ย้อนอันล่าสุด
/undo 12        ย้อนอันที่ระบุ
```

- **ไม่ใช่ version control** และไม่พยายามเป็น — git ทำเรื่องนี้ได้ดีกว่า
  นี่คือ "สิบนาทีหลังจากพูดว่า เอากลับมาเถอะ"
- **คัดลอกก่อนเขียน** เขียนพังก็แค่มีสำเนาส่วนเกิน ดีกว่าไม่มีสำเนา
- **ไฟล์ใหญ่เกินไปก็ยังเปลี่ยนได้** แต่บันทึกว่าย้อนไม่ได้ พร้อมเหตุผล
- **สำเนาเก่าจะถูกลบทิ้งตามอายุ** เก็บทุกเวอร์ชันตลอดกาลคือวิธีทำให้ดิสก์เต็มเงียบ ๆ
- **ย้อนกลับก็ถามก่อน** เพราะไฟล์อาจถูกแก้ด้วยมือไปแล้วหลังจากนั้น

## สมองที่สอง: Obsidian

โน้ตของ Thursday เคยอยู่ใน SQLite อย่างเดียว — ไม่มีกราฟ ไม่มี backlink
แก้เองไม่ได้ และพอ Thursday ไม่ได้รันก็เปิดอะไรไม่ได้เลย
**สมองที่สองที่มีแค่โปรแกรมเดียวเปิดได้ ก็ไม่ค่อยเป็นสมอง**

vault ของ Obsidian คือโฟลเดอร์ที่มีไฟล์ Markdown, `[[wikilink]]`, tag และ frontmatter
เท่านั้นเอง จึงไม่ต้อง integrate อะไร — Thursday อ่านไฟล์ เขียนไฟล์
และทุกอย่างที่มันเขียนคือไฟล์ที่คุณเปิดเอง แก้เอง sync เอง และเก็บไว้ได้แม้เลิกใช้ Thursday

```bash
THURSDAY_VAULT=~/Documents/MyVault     # โฟลเดอร์ที่มี .obsidian อยู่ข้างใน
```

```
"หาโน้ตเรื่องสัญญาเช่าให้หน่อย"        "ฉันรู้อะไรเกี่ยวกับซัพพลายเออร์เจ้านี้บ้าง"
"บันทึกสรุปนี้ลง vault"                "จดลง daily note ว่าคุยกับบัญชีแล้ว"
```

### กติกา: vault เป็นของคุณ ไม่ใช่ของ Thursday

- **โน้ตที่ Thursday เขียนเอง อยู่โฟลเดอร์ `Thursday/`** เห็นปุ๊บรู้ว่าใครเขียน ลบทีเดียวได้หมด
- **โน้ตที่คุณเขียน ไม่ถูกเขียนทับ** ลิงก์ไปอยู่ในบล็อกที่คั่นไว้ท้ายไฟล์
  ซึ่งถูกสร้างใหม่ทั้งก้อนทุกครั้ง — การแก้ของ Thursday จึงแตะได้แค่ข้อความที่ Thursday เขียนเอง
  (มีเทสต์ยืนยันว่าข้อความคุณยังอยู่ครบ)
- **frontmatter ไม่หาย** การทำ `tags:` ของคนอื่นหายเพราะ parser ฉลาดเกินไป ไม่คุ้ม
- **ทุกการเขียนผ่าน journal เดียวกัน** `/undo` เอาโน้ตกลับได้เหมือนไฟล์อื่น

### เชื่อมโยงความรู้ใหม่ได้เรื่อย ๆ

vault หมดประโยชน์ตอนโน้ตเลิกชี้หากัน ซึ่งเกิดขึ้นเพราะการจำว่าเมื่อแปดเดือนก่อนเขียนอะไรไว้
คือสิ่งที่คุณอยากได้ vault มาช่วยตั้งแต่แรก

```bash
/connect           # ดูว่ามีอะไรควรเชื่อมบ้าง
/connect apply     # เขียนลงไปจริง
```

บอกเหตุผลทุกครั้ง เรียงตามความน่าเชื่อถือ:

| หลักฐาน | ทำไมเชื่อได้แค่ไหน |
| --- | --- |
| `both tagged #งบ` | **คุณ**เป็นคนใส่ tag เอง ไม่ได้เดา |
| `both mention [[ทีมบัญชี]]` | สองโน้ตที่ชี้ไปที่เดียวกัน มักอยู่มุมเดียวกันของชีวิตคุณ |
| `close in meaning (0.84)` | จาก embedding ในเครื่อง อ่อนที่สุด และบอกตัวเลขออกมาตรง ๆ |

เหตุผลไม่ใช่ของประดับ — รายการลิงก์เปล่า ๆ คือสิ่งที่คุณจะเรียนรู้ที่จะเลื่อนผ่าน
แต่ "ทั้งคู่ติด #ภาษี" คือสิ่งที่คุณอ่าน และทำให้เห็นทันทีเวลามันเดาผิด

- **รันซ้ำได้เรื่อย ๆ** มันจำว่าเคยเสนออะไรไปแล้ว เดือนหน้ารันใหม่จะเจอแต่ของใหม่
- **ของเก่าไม่หาย** ลิงก์ที่เจอเมื่อเดือนก่อน ไม่ได้จริงน้อยลงในเดือนนี้
- **ไม่มีโมเดล embedding ก็ยังทำงาน** tag กับลิงก์ร่วมคือความเชื่อมโยงจริงโดยไม่ต้องใช้โมเดล
- อ่านก่อน เขียนทีหลัง และถามก่อนเขียนเสมอ

`thursday vault` บอกว่ามีกี่โน้ต เชื่อมกันแค่ไหน และอันไหน**ลอยอยู่**
(ไม่มีอะไรลิงก์ถึงเลย — พวกที่ vault ทำหายไปเงียบ ๆ)

อยากค้นด้วย "ความหมาย" ไม่ใช่ "คำ" ก็ทำดัชนี vault ด้วย `index_documents` แล้วใช้
`search_documents` ได้เลย ไฟล์ `.md` อยู่ในรายการที่อ่านได้อยู่แล้ว

## เปิดให้แอปอื่นใช้ (MCP server)

Thursday เป็น MCP **client** มาตลอด (เสียบ server คนอื่นได้) — นี่คือทางกลับกัน
Claude Code, Claude Desktop หรือแอปไหนก็ได้ เรียกสิ่งที่ Thursday รู้เกี่ยวกับคุณได้

```json
{ "mcpServers": { "thursday": { "command": "thursday", "args": ["mcp"] } } }
```

ให้ออกไปแค่ **ความจำ ไม่ใช่มือ**: โน้ต ความจำ ประวัติการคุย เอกสาร ปฏิทิน
เมลที่ยังไม่อ่าน การเตือน และแผนที่ทำค้างอยู่ —
**ไม่มีเชลล์ ไม่อ่าน/เขียนไฟล์ ไม่มีเบราว์เซอร์ ไม่คุมเดสก์ท็อป** (มีเทสต์ไล่ชื่อทีละอัน)
เพราะปลายทางคืออีกโปรแกรมหนึ่ง ที่อาจกำลังทำตามหน้าเว็บที่มันเพิ่งอ่านมา
และไม่มีใครอยู่ตรงนั้นให้กดยืนยัน

เขียนได้สองอย่าง ปลอดภัยทั้งคู่เพราะปลายทางอยู่ในบ้าน: `remember` เก็บความจำ
(คุณอ่านย้อนและลบได้) กับ `draft_email` ที่ **ยังต้องมาอนุมัติใน Thursday อยู่ดี**

## หมายเหตุด้านเทคนิค

- ค่าเริ่มต้นใช้ **Claude Opus 5** (`claude-opus-5`) พร้อม adaptive thinking และ
  `effort: medium` ซึ่งเป็นจุดที่สมดุลสำหรับผู้ช่วยที่ต้องตอบไว —
  ปรับได้ด้วย `--effort` หรือ `THURSDAY_EFFORT`
- เปิด **server-side fallback** ไว้ ถ้าคำขอถูกปฏิเสธ (`stop_reason: refusal`)
  จะถูกส่งต่อไปโมเดลสำรองอัตโนมัติแทนที่จะได้คำตอบว่าง
- **prompt caching**: บุคลิกและรายการ tool เป็น prefix ที่ไม่เปลี่ยน ส่วนเวลา
  ปัจจุบันและความจำถูกส่งเป็น mid-conversation system message ต่อท้าย
  จึงไม่ล้าง cache ทุกเทิร์น (โมเดลที่ไม่รองรับจะ fold เข้า user turn แทน)
- **ค้นเว็บ** ใช้ server tool `web_search_20260209` / `web_fetch_20260209`
  ของ Anthropic — ไม่ต้องมี API key ของ search engine
